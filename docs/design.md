# Quick Cmd 设计说明

基线版本：0.6.1。需求来源为 [spec.md](spec.md)，开发流程和项目约束见 [agent.md](../agent.md)。

## 1. 架构与职责

| 模块                                   | 职责                                            | 依赖边界                               |
| -------------------------------------- | ----------------------------------------------- | -------------------------------------- |
| `src/extension.js`                     | 装配 VS Code 接口、注册命令、参数解析与发送入口 | 不直接生成表单 HTML，不承担配置校验    |
| `src/model.js`                         | 数据校验、分组/命令操作、排序                   | 纯模型，不依赖 VS Code                 |
| `src/store.js`                         | 全局状态读写、串行更新                          | 不访问项目文件；读返回独立副本         |
| `src/tree.js`                          | 原生“分组 → 命令”树、状态、拖拽和撤销           | 数据从存储获取，不自行持久化           |
| `src/group-decoration.js`              | 分组文字及图标的主题颜色                        | 只装饰专用分组资源，不向命令传播       |
| `src/editor.js`                        | 编辑会话、草稿、保存冲突、侧栏/宽编辑器协调     | 对客户端消息校验，保存仍通过模型与存储 |
| `media/editor-client.js`               | 表单、步骤、校验反馈、环境变量表格              | 通过消息交互，不直接操作终端或文件     |
| `src/terminal.js` / `src/variables.js` | 终端管理、状态观测、目录与变量展开              | 不把“已发送”视为“执行成功”             |
| `src/transfer.js`                      | 显式 JSON 导入/导出                             | 导入校验后确认替换；无项目配置监听     |
| `src/i18n.js` / `media/i18n.js`        | 发行版语言解析、共享翻译和错误本地化            | 构建语言覆盖宿主语言；开发时跟随宿主   |

## 2. 数据与一致性

- `globalState` 的 `quickCmd.globalConfig` 保存唯一全局集合；版本字段保持 `1`。
- `ConfigStore.update` 将所有读—修改—校验—写入串行化，失败后队列可继续；错误配置不写入。
- 模型 ID 在重命名和组间移动后不变。树使用稳定标识，撤销前比较当前配置与操作后的快照，防止回滚其他修改。
- 项目文件夹仅作为执行目录或文件变量上下文；不是配置保存范围。
- JSON 导入先解析和校验，再请求替换确认，不主动执行导入的命令。

## 3. 编辑会话与消息

会话包含选择信息、唯一 `token`、递增 `revision`、当前 `raw` 草稿、`baseline` 保存基线和 `original` 存储快照。草稿写入当前 VS Code 工作区状态，不能触发命令执行。

| 消息                  | 方向                  | 含义                                             |
| --------------------- | --------------------- | ------------------------------------------------ |
| `ready` / `load`      | 客户端请求 / 宿主响应 | 初始化当前草稿及基线                             |
| `draft` / `revision`  | 双向                  | 提交草稿、检查会话与版本并确认版本               |
| `save` / `saved`      | 客户端请求 / 宿主响应 | 保存提交快照，返回对应基线；后续输入仍可能未保存 |
| `error`               | 宿主到客户端          | 保留输入并显示本地化错误                         |
| `expand` / `readOnly` | 客户端请求 / 宿主广播 | 宽编辑器接管编辑，侧栏只读同步                   |
| `reopen`              | 客户端到宿主          | 处理草稿后重新读取已保存版本                     |

切换对象依次处理当前草稿、读取目标并生成新会话。保存比较 `original` 与存储当前值；不同则拒绝覆盖。宽编辑器与侧栏共享会话，只有宽编辑器可写，关闭后恢复侧栏写入。

表单把末尾回车作为组级设置，序列化时映射为中间步骤 `execute: true` 和最后一步的实际选项；布局操作不会改动选项。无效环境变量行通过草稿元数据保留，不作为有效环境变量写入。

交互模式与表单可见性分别使用 `quickCmd.editMode`、`quickCmd.editing`：启动时均为 `false`。普通模式单击命令按保存的回车选项发送，不能打开编辑栏；编辑模式单击只加载编辑器，不能发送。右上角进入编辑模式只切换模式，没有选中命令时保持编辑栏隐藏；显式新建或编辑命令同时进入编辑模式。

所有打开编辑器的路径通过统一入口同步模式上下文。右上角完成操作先等待保存并处理草稿；取消或失败则保持编辑模式，成功后关闭表单/宽编辑器、清空会话并恢复普通模式。模式变化更新树的动作提示和行内按钮。搜索在普通模式选择后发送，在编辑模式选择后编辑，不再追加第二次动作选择。

工具栏直接提供现有常用功能；折叠全部使用原生树命令，设置打开插件配置。命令行描述显示可截断的 Shell 文本摘要，完整文本保留在提示中。

## 4. 原生树与颜色

继续使用 VS Code Tree View，不以 Webview 重写命令树。分组 `resourceUri` 使用 `quick-cmd-group` 专用 scheme，`GroupDecorationProvider` 返回 `ThemeColor('quickCmd.groupForeground')` 且 `propagate: false`。文件夹图标使用同一颜色；普通命令没有该资源装饰。

颜色在 `package.json` 声明深色、浅色和高对比度默认值，允许用户通过 `workbench.colorCustomizations` 覆盖。原生文字装饰由 `explorer.decorations.colors` 控制；不覆盖用户设置，选中和悬停状态由宿主渲染。

## 5. 终端与变量

新建终端始终使用专用终端；复用仅在 Shell 集成确认空闲且目录/环境签名一致时进行。活动终端不能应用专用目录或环境，状态不确定时提示。关闭专用终端是停止操作的实现边界。

跟踪最近文本编辑器 URI（Uniform Resource Identifier，统一资源标识符），避免宽 Webview 激活后文件变量丢失。全局命令在多根工作区中按最近文本文件确定目录，缺省取第一个目录。

命令变量按 `posix`、`powershell` 或 `cmd` 规则引用；目录和环境使用纯文本展开。步骤合并发送保持明确边界，不承诺独立步骤进程管理。

## 6. 中英文构建

源树默认目录保持不变：`package.nls.json` 为英文，`package.nls.zh-cn.json` 为中文；共享运行时目录维护翻译。开发模式随 VS Code 语言，发行模式由包元数据固定语言。

`scripts/package-variants.js` 在 `.build/zh-cn` 和 `.build/en` 建立隔离目录：

1. 复制运行时代码和所需说明，不复制测试、开发依赖、工程文档或构建脚本。
2. 保持 `publisher`、`name`、`version` 相同，写入 `quickCmdBuildLanguage`。
3. 只放入目标语言的默认 `package.nls.json`，防止宿主语言覆盖所选版本。
4. 调用锁定的 VSCE（Visual Studio Code Extensions 打包工具），输出 `dist/quick-cmd-v<version>-zh-cn.vsix` 和 `dist/quick-cmd-v<version>-en.vsix`。
5. `scripts/verify-packages.py` 检查 ZIP、版本、语言、扩展标识和运行时文件，排除依赖泄漏，再生成 `SHA256SUMS`。

两包使用同一扩展标识，用户选择其一安装；同一宿主/配置档案中切换语言包保留全局命令，不支持两包同时安装。

## 7. 持续集成与发布

CI（Continuous Integration，持续集成）在合并请求和主分支执行安装、检查、测试、双语打包与解包验证。发布工作流使用同一命令，先上传工作流产物，再创建含两包和校验和的草稿发布，最后转为正式发布。

v0.6.0 按用户要求执行一次历史重置：仅删除已核实的旧版本 `v0.2.0`、`v0.3.0`、`v0.3.1`、`v0.4.0`、`v0.5.0` 及其标签。清理发生在新包通过验证并上传草稿之后。固定白名单不会匹配未来版本或其他标签；普通版本发布不清理历史。已正式发布的同版本不会在重复运行时被覆盖。

## 8. 测试边界

模型测试验证约束与排序，存储测试验证全局单集合和并发，终端测试验证发送/状态边界，会话与 DOM 测试验证草稿和表单。构建测试验证跨宿主语言固定发行语言、同扩展标识与源树不被改写；颜色测试验证专用资源与不向子项传播。

实际 VS Code 的深浅色、高对比度、选中行对比度、原生拖拽和不同侧栏宽度需要单独人工或图形宿主验收，不以 DOM 测试冒充已完成。
