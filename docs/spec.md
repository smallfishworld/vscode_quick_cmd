# Quick Cmd 需求规格

基线版本：0.11.2。本文件是当前需求的唯一来源；历史实现笔记不作为需求依据。

## 1. 目标与边界

为 VS Code 的本地和 Remote SSH 开发提供常用终端命令管理。用户在侧栏直接维护分组和命令，明确选择编辑、保存、发送。Windows、macOS、Linux 均使用对应扩展宿主的集成终端。

只提供全局命令集合，树形结构固定为“分组 → 命令”。不提供项目配置、范围选择或项目命令迁移。不自动执行命令，不承担等待依赖、并行调度、失败中断等工作流编排。

## 2. 功能要求与验收

| 编号  | 需求       | 验收条件                                                                                                               |
| ----- | ---------- | ---------------------------------------------------------------------------------------------------------------------- |
| FR-01 | 分组管理   | 新建、重命名、删除、拖拽及上下移动；分组是列表根节点，删除前确认                                                       |
| FR-02 | 命令管理   | 一次填写名称、步骤、目录等字段；编辑、创建副本、删除和组间移动可用                                                     |
| FR-03 | 选中与发送 | 单击命令按配置发送；每条命令最右侧悬停或键盘聚焦时显示编辑、运行按钮，编辑不触发发送，运行按钮遵循已保存的末尾回车选项；删除通过行级右键的原生上下文菜单，删除仍确认；无全局编辑开关                                     |
| FR-04 | 编辑保护   | 切换前提示保存/放弃/取消；草稿可恢复；失败或外部冲突不覆盖用户修改                                                     |
| FR-05 | 保存反馈   | 明确区分未保存、保存中、已保存；保存期间新输入仍为未保存                                                               |
| FR-06 | 编辑布局   | 编辑栏默认隐藏，仅新建/行尾编辑时显示；编辑栏自身可结束编辑并保护草稿；标题栏同时提供“保存并完成编辑”（✓，先保存草稿再退出，保存失败保持编辑）与“关闭编辑”（×，脏数据走保存/放弃/取消确认）两个入口；两者退出后焦点回到命令列表视图，不停留在终端或空编辑视图；列表可独立移动，表单与列表均紧凑        |
| FR-07 | 多步骤     | 最多 32 步；支持命名、折叠、拖拽、键盘移动、删除撤销和变量插入                                                         |
| FR-08 | 末尾回车   | 整组命令只有一个末尾回车选项，增删/排序不改变其值                                                                      |
| FR-09 | 终端       | 支持新建、确认空闲后复用专用终端、当前活动终端；后者不能附带专用目录/环境                                              |
| FR-10 | 状态       | Shell 集成可用时显示运行及退出结果；无可靠信息时明确状态未知                                                           |
| FR-11 | 参数与环境 | 支持工作区、文件、环境及输入变量；环境变量用表格或 JSON 编辑，错误输入保留；命令图标提供约 30 个 Codicon 预设加自定义名称，选项与命令列表使用同一套字体渲染，两处显示一致 |
| FR-12 | 全局保存   | 全局扩展状态保存一份集合；并发修改串行；任何项目配置文件均不读取或写入                                                 |
| FR-13 | 搜索与交换 | 搜索后选择命令直接发送；右上角按钮提供 JSON 导入/导出，替换前确认                                                         |
| FR-14 | 快捷键     | 搜索快捷键可用；编辑器内保存可用；命令可生成按 ID 发送的绑定                                                           |
| FR-15 | 语言发行   | 仅产出一个 VSIX（Visual Studio Code Extension 安装包）；依据 VS Code UI 语言选择中文或英文，标题、菜单、表单、状态、提示、错误一致，非中文默认英文 |
| FR-16 | 分组视觉   | 分组和命令同色，不显示命令数量；默认字体跟随 VS Code 界面，命令比宿主小 1px、分组比命令大 2px；分组展开时在折叠箭头下方显示缩进竖线；行尾只保留编辑/运行按需显示，删除走右键菜单；窄栏文本省略不挤掉行尾按钮                                    |
| FR-18 | 可选命令预设 | 仓库的 `presets/` 提供完整与 Git 专用两类 JSON，均有中英文版本；通过现有模型校验、ID 唯一、单步骤、所有修改远端或工作区状态的关键命令开启确认；仅由用户手动导入，原有整份替换语义不变，不自动执行，不增加项目级配置 |
| FR-19 | 单包发行及 Marketplace | GitHub Release 和 VS Code Marketplace 使用同一个 VSIX：`quick-cmd-v<version>.vsix`；内含英文默认及简体中文 NLS 资源、预设 JSON；不再构建固定中英文包；需要发布者授权才能上传 Marketplace |
| FR-21 | Marketplace 图标 | 顶层 manifest 配置 `icon: media/icon.png`；该图片必须为实际 128×128 PNG；构建和 VSIX 解包测试验证图片存在、尺寸和字节一致；原活动栏 SVG 不变 |
| FR-20 | Marketplace 分类合法性 | `package.json` 的 `categories` 只能使用 VS Code 官方支持的分类；当前工具类插件使用 `Other`，构建和测试时检查，阻止无效分类进入 VSIX |
| FR-17 | 发布验证   | 唯一 VSIX 采用现有扩展标识，包含中英文资源且与源码一致；验证内容及 SHA-256 校验和后才能正式发布                                                     |

## 3. 交互约束

- 命令列表不增加全局或项目根节点；新建不询问保存范围。
- 编辑栏默认隐藏；右上角保留新建、搜索、导入导出、折叠、刷新、设置，移除全局编辑/完成按钮。行尾铅笔是悬停操作入口；结束编辑按钮只放在编辑栏，标题栏同时提供“保存并完成编辑”（✓）和“关闭编辑”（×）两个入口。✓ 直接保存草稿并退出，× 在脏数据时弹保存/放弃/取消确认；两者退出后焦点回到命令列表视图。
- 命令名称后展示命令文本摘要；运行状态与完整文本仍可通过提示查看。
- 工作目录、终端使用方式可直接看到；描述、图标、环境等低频配置放入高级设置，高级设置默认展开。
- 图标操作提供本地化提示和无障碍名称，选项与命令列表使用同一 Codicon 字体渲染；列表名称和命令摘要使用同一界面字体，编辑输入框保留等宽字体，窄栏不产生整页水平溢出。
- 列表使用主题前景色，字体可通过 `quickCmd.listFontSize` 调整，命令比宿主小 1px、分组比命令大 2px。不修改其他视图字体或全局主题。列表与编辑栏均为 VS Code 可移动的视图，可通过标题栏“移动视图”合并到资源管理器等容器。
- 仅发行一种安装包，`package.nls.json` 和 `package.nls.zh-cn.json` 由 VS Code 按 UI 语言自动选择；扩展运行时通过 `vscode.env.language` 选择 UI 文案，切换 VS Code 显示语言并重载后生效；已有全局命令始终保留。
- 用户命名、Shell 文本、路径、JSON 字段和变量标识保持原文；不能把系统界面的翻译混用与用户内容混淆。


- 右键命令或分组时，在鼠标位置显示原生上下文菜单，不打开顶部快速选择框；菜单操作绑定右键目标，打开菜单不发送命令。

## 4. 执行语义

步骤使用换行拼接，一次调用终端发送接口。中间步骤按换行分隔；最后一步决定是否附加末尾回车。没有等待前一步完成，也没有失败即停止。

取消末尾回车不能保证多行内容完全不执行；嵌入换行和交互程序消费后续输入的行为取决于终端与 Shell。仅预填优先使用单行、单步骤。工作区未信任时只能编辑，不能发送。

## 5. 数据约束

| 对象/字段 | 约束                                                                         |
| --------- | ---------------------------------------------------------------------------- |
| 配置      | `version: 1`、`groups` 数组；严格 JSON                                       |
| 数量      | 最多 200 个分组、总计 1000 条命令                                            |
| 标识/名称 | 稳定唯一 ID；分组/命令名称非空、最多 128 字符                                |
| 步骤      | 1–32 步；命令非空、每步最多 8192 字符、合计最多 32768 字符；名称最多 64 字符 |
| 目录/描述 | 目录最多 2048 字符；描述最多 512 字符                                        |
| 环境变量  | 有效变量名与字符串值；值最多 2048 字符                                       |

命令可包含 `title`、`steps`、`cwd`、`terminal`、`confirm`、`description`、`icon`、`env`。模型仍可读单条 `command` 表达形式；这不意味着恢复项目范围或增加迁移功能。

## 6. 质量与发行门槛

- 无第三方运行时依赖；测试及打包工具仅为锁定版本的开发依赖。
- 语法检查、模型/存储/终端/编辑会话/DOM（Document Object Model，文档对象模型）交互/语言包测试必须通过。
- 实际构建并解包验证唯一多语言 VSIX，生成仅包含这一安装包的 SHA-256 校验文件。
- 自动化 DOM 测试不替代真实 VS Code 中的主题、颜色、字体、拖拽及窗口尺寸验收；发布说明须如实陈述验证范围。
- 新需求必须先更新本文件的行为和验收条件，再同步设计与实现，流程见根目录 `agent.md`。
