# Quick Cmd — VS Code 插件需求规格说明

> 版本：v0.1.0（首版基线）  
> 状态：P0 已实现；P1/P2 为后续迭代计划。  
> 目标：可视化维护常用 Shell 命令，并从 VS Code 左侧命令栏一键在内置终端执行。

## 1. 背景与目标

在 C/C++、嵌入式、脚本和日常开发过程中，编译、清理、运行、部署、设备连接与日志查看等任务往往反复执行。希望在 VS Code 左侧统一维护一组命令，避免频繁复制粘贴命令行，也方便在不同项目之间切换。

**核心原则**：低学习成本、原生 VS Code UI、明确的执行时机、配置可共享、兼容本地与 Remote SSH 工作区。插件不负责替代复杂的任务编排系统。

## 2. 目标用户与使用场景

- **日常开发**：一键运行构建、清理、Git 状态检查、测试等命令。
- **嵌入式开发**：一键构建固件、连接设备、部署、打印日志。
- **多项目开发**：不同项目有独立配置；跨项目通用命令作为全局命令保存。
- **远程开发**：连接 Remote SSH 时，命令在 VS Code 对应的远程终端运行。

## 3. 信息架构

左侧 Activity Bar 增加 **Quick Cmd** 图标，点击后显示 Tree View：

```text
Quick Cmd
├── Global commands
│   └── Utilities
│       ├── Git status       ▶
│       └── Check version    ▶
├── project-a
│   ├── Build
│   │   ├── Debug build      ▶
│   │   ├── Release build    ▶
│   │   └── Clean            ▶
│   └── Device
│       ├── Deploy           ▶
│       └── View log         ▶
└── project-b
    └── Tests
        └── Unit tests       ▶
```

点击命令文字或行内播放按钮即可运行。右键命令提供编辑、删除；右键分组提供重命名、删除、添加命令；顶部提供添加命令、添加分组、刷新。

## 5. 配置数据格式

项目配置文件路径：`<workspaceFolder>/.vscode/quick-cmd.json`

```json
{
  "version": 1,
  "groups": [
    {
      "id": "build",
      "title": "Build",
      "commands": [
        {
          "id": "debug",
          "title": "Debug build",
          "command": "cmake --build build -j8",
          "cwd": "${workspaceFolder}"
        }
      ]
    }
  ]
}
```

**约束：**

- 配置版本必须为整数 `1`，顶层必须有 `groups` 数组。
- 分组、命令均有稳定且在单个配置文件内唯一的 ID。
- 分组和命令名称不能为空（上限 128 字符）。
- Shell 命令不能为空（上限 8192 字符）。
- `cwd` 可选（上限 2048 字符）。
- 插件不自动执行共享配置中的命令；不对 `command` 文本做自动变量插值。
- 用户可直接修改 JSON，保存后 Tree View 自动刷新。

## 6. 终端策略

**首版：每一次运行都创建新的 VS Code 内置终端。**

这是有意选择：对于长时间运行的编译、串口/网络日志和远程连接命令，复用同一个终端有可能把新命令输入到正在运行的程序。终端运行完毕后不自动关闭，保留日志输出。

执行流程：点击命令 → 重新读取当前配置 → 校验工作区信任 → 解析工作目录 → 创建终端 → 发送 Shell 文本 → 显示终端。

本阶段不会假定命令已经执行成功，暂不提供未经验证的成功/失败指示灯。

## 7. 非功能需求

- **可移植性**：Windows、macOS、Linux；Remote SSH 根据扩展宿主环境执行。
- **低依赖**：无需第三方运行时包，使用 VS Code 官方 API。
- **可维护性**：独立划分数据模型、配置读写、终端执行、视图和入口模块。
- **数据安全**：工作区配置写入采用临时文件 + 重命名，避免失败时截断旧文件；更新操作按配置源串行执行。
- **清晰错误处理**：配置无效时不自动修复/覆盖，直接提供诊断信息；删除前确认。

## 8. 版本验收标准

1. 安装/启动后，左侧出现 Quick Cmd 图标。
2. 能创建项目分组、加入 `echo hello` 命令，单击后在新终端输出 hello。
3. 编辑命令后再次执行能使用新的内容，删除前有确认。
4. 重开工作区仍可加载 `.vscode/quick-cmd.json`。
5. 全局命令跨工作区可用，多根工作区的项目命令互不混淆。
6. 两次快速点击会创建两个终端，不向正在运行的终端注入第二条命令。
7. 配置格式出错时展示错误，不会静默覆盖原文件。
8. 未信任工作区无法执行保存的 Shell 命令。
9. 静态语法检查和单元测试通过；CI 配置能够打包 VSIX。

## 9. 后续迭代

**P1（建议下个版本）**

- 终端复用模式（只在可可靠判断空闲时复用）、停止进程。
- 结合 VS Code Shell Integration 获取退出码并显示运行状态。
- 自定义环境变量、执行前参数输入、命令图标。
- 命令复制、搜索过滤、排序。
- JSON 配置迁移和导入/导出。

**P2（中长期）**

- 复杂命令编排（串行/并行执行与失败中断策略）。
- 拖拽排序和组间移动。
- 快捷键绑定、历史记录和收藏。
- 插件本地化和可视化高级表单编辑。

## 10. 边界与风险

- Shell 命令由用户显式定义并执行，本插件不提供运行容器沙箱。
- 命令成功/失败状态在 v0.1.0 不做保证。
- 纯虚拟文件系统工作区不在支持范围；Remote SSH 需要真实远程文件系统和终端。
- 对于需要稳定任务状态、问题匹配器等复杂功能，后续可评估与 VS Code Tasks API 集成。
