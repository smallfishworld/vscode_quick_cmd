# Quick Cmd — VS Code 快捷命令面板

简体中文 | [English](README.md)

在 VS Code 侧栏保存、管理和编辑常用终端命令。所有命令全局可用，支持分组、多步骤、变量插入及远程开发；无第三方运行时依赖。

## 安装和使用

需要 VS Code **1.93 或更新版本**。从 [Releases](https://github.com/smallfishworld/vscode_quick_cmd/releases) 下载 `.vsix`，在扩展视图选择“从 VSIX 安装”。也可以下载合并请求检查生成的安装包。

1. 点击活动栏 **Quick Cmd** 图标。
2. 点击“新建命令”，选择分组；在分组旁点击 `＋` 可以直接在该分组新建。
3. 编辑栏默认隐藏，新建或编辑命令时才显示；在编辑栏一次填写名称、命令内容、工作目录和终端使用方式，点击“保存命令”。
4. **单击命令主体按配置发送；鼠标移入命令行时，最右侧显示编辑、运行按钮；删除改由右键命令弹出的原生菜单完成，删除前仍确认。编辑只打开表单。键盘聚焦时也显示这些按钮。** 在编辑栏工具栏点击“完成编辑”或右上角 × 关闭，处理草稿后收起。
5. 搜索按钮或 `Ctrl+Alt+Q`（macOS：`Cmd+Alt+Q`）可查找命令，选择后直接发送。

发行版提供 `quick-cmd-v0.8.0-zh-cn.vsix`（固定中文）和 `quick-cmd-v0.8.0-en.vsix`（固定英文），请选择其一安装。两包共用扩展标识，替换语言包沿用同一宿主/配置档案中的全局命令，不支持同时安装。开发模式仍跟随 VS Code 显示语言；用户填写的名称、命令和变量不翻译。

## 命令列表

- 分组和命令使用相同主题文字颜色，不显示命令数量。名称与摘要统一使用 VS Code 界面字体和字重；命令比宿主小 1 像素，分组比命令大 2 像素。`quickCmd.listFontSize=0` 表示跟随宿主，正值可自定义命令字号（10–18 像素）。
- 分组展开时，在折叠箭头下方绘制一条缩进竖线，让命令列始终可见。
- 通过原生视图标题的“移动视图”菜单，可把命令视图合并到资源管理器等容器；字号设置只影响本插件。
- 列表直接显示 **分组 → 命令**，不再区分全局与项目，也不再显示范围根节点。命令统一保存在 VS Code 扩展的全局状态中。
- 命令、分组支持拖拽排序；命令可以拖入其他分组；分组可拖到列表空白处移动到末尾。
- 拖动后保留选中位置，提供撤销。之后配置已变化时，撤销会被拒绝，避免覆盖其他修改。
- 右键命令或分组时，在鼠标旁显示原生菜单，提供创建副本、删除、上移/下移、快捷键配置等操作；命令删除只在这里，行尾不再放删除按钮。分组栏右上角按钮提供导入/导出。
- 运行状态优先于自定义图标显示。没有可靠状态信息时显示“状态未知”，不把发送成功当成执行成功。

## 编辑栏

右上角提供新建分组、新建命令、搜索、导入、导出、折叠全部、刷新和设置；导入改用受支持的向下箭头图标。编辑栏默认隐藏，新建或点击悬停显示的命令行尾铅笔时才显示，不再提供全局编辑模式开关。表单同步缩小字号、控件和留白。编辑栏标题栏同时提供“完成编辑”和 × 两个关闭入口。收起前处理未保存内容，取消则保留表单；保存后仍可继续编辑。

- **草稿保护**：切换命令前，可选择保存、放弃修改或取消。草稿保存在当前 VS Code 工作区状态中，重新加载扩展后可恢复；草稿不会自动执行或自动保存命令。
- **准确保存状态**：显示未保存、保存中和已保存。保存期间继续输入的内容仍标记为未保存。
- **固定底部操作区**：提供保存和“保存并发送”；编辑栏获得焦点时可用 `Ctrl+S` / `Cmd+S` 保存。
- **主编辑区模式**：点击顶部展开按钮打开宽编辑器，和侧栏共用草稿。宽编辑器打开期间，侧栏同步显示但暂时只读，关闭宽编辑器后恢复编辑。
- **步骤操作**：支持拖拽、上移/下移、折叠和删除后撤销；命令输入框内 `Alt+↑` / `Alt+↓` 移动步骤。窄侧栏通过“更多操作”按钮展开操作菜单。
- **命令输入**：自动调整输入高度，支持插入常用文件和工作区变量。步骤名称可选。
- **常用设置前置**：工作目录、终端使用方式直接显示；确认发送、描述、图标、环境变量放入高级设置。
- **图标选择**：内置常用图标预览；也可以填写自定义 Codicon 标识。
- **环境变量**：默认通过名称/值表格编辑，可切换为 JSON；错误或未完成的输入会保留。
- **外部修改保护**：命令被配置文件或其他窗口修改后，保存会提示冲突；顶部“重新打开已保存版本”可在确认后重新载入。

## 多步骤与末尾回车

每条命令最多 **32 个步骤**。所有步骤用换行连接，**一次发送到同一个终端**；不是等待前一步完成的任务工作流，也不会自动在失败后停止。需要失败即停止时，请自行使用适合所用 Shell 的组合语法，例如 POSIX Shell 的 `&&`。

“发送末尾回车”是整组命令的选项：增删或移动步骤不会改变它。保存时，中间步骤的 `execute` 均为 `true`，最后一步保存该选项的值。

**取消末尾回车不保证整段内容不会执行**：中间步骤及命令文本本身仍可含换行，具体行为取决于终端和 Shell。需要仅预填时，建议使用单步骤、单行命令。交互式程序可能消费后续输入，不适合作为这种多步骤组合的中间步骤。

## 终端使用方式

| 方式                   | 行为                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------ |
| 每次新建终端           | 默认值；每次创建专用终端，保留原有输出                                               |
| 优先复用空闲的专用终端 | 仅在 Shell 集成确认空闲且目录、环境配置一致时复用，否则新建                          |
| 使用当前活动终端       | 沿用活动终端的目录和环境；不能同时配置自定义工作目录或环境变量，无法确认空闲时会提示 |

工作区未被信任时可以编辑，但不能发送命令。插件不会在启动或配置变化时自动执行命令。“停止命令并关闭终端”仅适用于专用终端，不能停止用户的非专用活动终端。

## 配置和变量

命令保存在全局状态中，可通过右上角按钮导入/导出严格 JSON。项目中的 `.vscode/quick-cmd.json` 不再读取或写入；没有项目命令迁移逻辑。导出文件结构如下：

```json
{
  "version": 1,
  "groups": [
    {
      "id": "build",
      "title": "编译构建",
      "commands": [
        {
          "id": "debug-build",
          "title": "编译并准备查看日志",
          "steps": [
            {
              "title": "编译",
              "command": "cmake --build build -j8",
              "execute": true
            },
            {
              "title": "日志",
              "command": "tail -f build/build.log",
              "execute": false
            }
          ],
          "cwd": "${workspaceFolder}",
          "terminal": "new",
          "icon": "tools",
          "confirm": false,
          "env": { "CMAKE_BUILD_PARALLEL_LEVEL": "8" }
        }
      ]
    }
  ]
}
```

支持 `${workspaceFolder}`、`${file}`、`${fileDirname}`、`${fileBasename}`、`${fileBasenameNoExtension}`、`${relativeFile}`、`${env:NAME}`、`${input:name}`。

命令内容中的变量按 Shell 规则自动加引号，不需要自行在变量两侧加引号；工作目录、环境变量按纯文本展开。`quickCmd.shellType` 支持 `auto`、`posix`、`powershell`、`cmd`。

右键“复制快捷键配置”可以生成 `quickCmd.runById` 的按键配置，参数为 `{"id":"命令标识"}`。

## 开发与验证

建议使用 Node.js 22：

```bash
npm ci
npm run check
npm test
npm run package
python3 scripts/verify-packages.py
```

测试包括配置、终端发送、草稿会话以及通过 Happy DOM 运行的命令列表和编辑器交互。Happy DOM 仅用于开发测试，不打入扩展运行包。界面测试不能代替实际 VS Code 中的主题、字体、拖拽和尺寸验收。

构建输出在 `dist/`，包括中英文两个安装包和 `SHA256SUMS`。GitHub Actions 对两个语言包同时构建与解包验证；发布工作流先准备完整草稿，再发布同版本双语安装包。

工程文档仅保留 [需求规格](docs/spec.md) 和 [设计说明](docs/design.md)；修改项目遵循根目录 [agent.md](agent.md)。
